# agent-versions: guide for AI agents and contributors

"Dependabot for AI coding". This one codebase ships a CLI, an MCP server
(stdio and HTTP), a Claude Code plugin, a GitHub Action, and a data feed.
Read this before you change anything.

## Hard rules

1. **Zero runtime dependencies.** Node standard library only. CI fails if
   `dependencies` appears in `package.json`. The project runs through `npx github:…`
   and as a plugin with no install step, and every dependency would be supply-chain risk.
2. **Anything written to a user's file passes `src/validate.js`.** Never bypass
   `isSafeVersion` / `isValidPackageName`, and never build a registry URL from an
   unvalidated name. Edits replace exact `start`/`end` spans; never regenerate
   a whole manifest.
3. **The remote MCP mode stays read-only.** Tools that touch the filesystem must not
   set `remote: true` in `src/mcp.js`. Local tools must go through `projectPath()`.
4. **Workflows:** pin every action to a full commit SHA with a version comment.
   Declare `permissions` per job, starting from `permissions: {}`. Never use
   `pull_request_target`, and never interpolate `${{ }}` inputs inside `run:`
   (pass them through `env:`).
5. **Never hand-edit `data/latest.json` or `VERSIONS.md`.** They are generated by
   `npm run collect`. The live feed is published to the `data` branch by the
   `update-snapshot` workflow; the copy on `main` is the bundled fallback,
   refreshed at release time.
6. Every behaviour change gets a test. `npm test` must pass on Node 20, 22 and 24.

## Map

| Path | What it does |
|---|---|
| `bin/agent-versions.js` | CLI entry |
| `src/cli.js` | Commands: check, update, latest, tools, stack, init, mcp |
| `src/engine.js` | Finds manifests, resolves latest versions, computes and applies bumps |
| `src/manifests/*.js` | One parser per ecosystem. Returns deps with `start`/`end` offsets of the version text |
| `src/semver.js` | Version comparison and precision-preserving bumps |
| `src/registries.js` | npm, PyPI, crates.io sparse index, Go proxy and GitHub releases lookups |
| `src/validate.js` | Security boundary for names and versions |
| `src/mcp.js` | MCP server: JSON-RPC handlers, stdio and HTTP transports, limits |
| `src/companions.js` | Rules and MCP config writers for Cursor, Windsurf, Copilot, Cline, Kiro, … |
| `src/collect.js`, `scripts/collect.js` | Build the published snapshot from `sources.json` |
| `src/snapshot.js` | Load the snapshot (remote, then bundled fallback) |
| `.claude-plugin/`, `.mcp.json`, `skills/`, `hooks/` | Claude Code plugin |
| `action.yml`, `scripts/action-report.js` | GitHub Action |
| `templates/` | Files written by `init` |
| `api/mcp.js` | Serverless entry for the remote connector |

## Common tasks

```bash
npm test                                   # everything, offline
node bin/agent-versions.js check <dir>     # manual run
GITHUB_TOKEN=$(gh auth token) npm run collect   # regenerate the feed (~1-2 min, network)
node bin/agent-versions.js mcp --http      # connector on 127.0.0.1:3000/mcp
claude plugin validate .                   # plugin manifests
```

- **Track a new tool:** add it to `sources.json` (schema in CONTRIBUTING.md), run collect, and commit the data.
- **Support a new companion:** add an entry to `COMPANIONS` in `src/companions.js`
  with its rules path and MCP format, then add it to `test/companions.test.js`.
- **Add an ecosystem:** add a parser plus a lookup plus validation rules, with tests for each.

## Releasing

1. Bump `version` in `package.json` **and** `.claude-plugin/plugin.json`.
2. Refresh the bundled fallback: `GITHUB_TOKEN=$(gh auth token) npm run collect`.
3. Add a `CHANGELOG.md` entry.
4. Open a PR and merge it to `main` (direct pushes are blocked). Then tag `vX.Y.Z` and create a GitHub release. `init` pins the
   Action to `v<package version>`, so the tag must exist before users run `init`.
